## 1. 决策目的

T013 长期卡在三个阻塞项上：

- `B-012` 品牌福利官服务项：原型 3 类 vs 历史稿 T08 的 4 服务卡；
- `B-013` 智能客服聊天视觉、热门问题、关键词识别行为；
- `B-014` 人工客服排队：只保留排队中/已接入两态，队列递减等 mock 不得引入。

用户在本轮任务中直接给出前两项与第三项的判定口径：福利官按摹客 3 类服务纠正历史 4 项；智能客服只做欢迎、对话、发送失败/重试、企微客服入口；#70 只做「排队中 / 已接入」两个确定状态，不做人数递减、倒计时或虚假队列。

本记录据此关闭 `B-012`，并把 `B-013` / `B-014` 中**已获口径的部分**关闭、**仍缺原型依据的部分**降级为夹具登记项，使 T013 可在不倒推产品规则的前提下交付四个节点的确定状态。

## 3. 决策细节

### 3.1 福利官 3 类服务（D-038）

服务项文案与徽标来自 `WELFARE_OFFICER_SERVICES`。原型 §8 未给出副标题与跳转目标，故渲染为**说明列表而非可点按钮**，避免造出未确认的下级页面；该缺口登记在 `WELFARE_OFFICER_RULE_STATUS`。

### 3.2 智能客服四件事（D-039、D-040）

- 欢迎态首屏**只有一条**小诗欢迎语，不预置历史对话、不铺热门问题；
- 用户消息经 `sending`（`CHAT_SEND_LATENCY_MS = 700`）落到确定性结果，成功后追加 `CHAT_BOT_FALLBACK_REPLY` 兜底回答 —— 原型未给出问答库，故不假装能答具体问题；
- 失败气泡带 `CHAT_SEND_FAILED_HINT` 与「重试」，重试复用同一条消息文本再走一次判定；`CHAT_FAILED_MESSAGES` 的用户消息刻意**不含**失败关键词，以保证「失败 → 重试 → 成功」可被证据脚本走通；
- 输入「人工客服 / 转人工 / 人工」等同于点击页内入口，直接打开 #71（`isChatHumanRequest`）；
- 壳层 `MobileLayout` 的 `titleBarAction` 只支持 `'settings' | 'notifications'`，故「企微客服」入口渲染在**页面体内**而非标题栏右上角。

### 3.3 #71 企微引导弹层（D-041）

原型 §10 的弹层只列出「取消」，因此**弹层内只实现「取消」**。#71 → #70 的前进动作原型未给出，属未确认业务规则，按项目硬规则**不实现**；仅登记于 `CHAT_RULE_STATUS.humanQueueEntry`。#70 本轮暂通过直达路由 `/service/chat/human?state=queuing|connected` 与 `?debug=1` 调试面板验收，不伪造正式业务入口。`scripts/capture-t013.mjs` 对此加了**负向断言**（弹层内「已添加，进入人工客服」按钮数必须为 0），防止该未确认入口被重新加回。

企微为外部能力，本项目不做真实跳转，仅以 `WecomQrPlaceholder` 占位（`role="img"` + 明确的「QR Placeholder」字样），不伪装成可扫码的真二维码。

### 3.4 排队两态与历史保留（D-041、D-042）

- `?state=queuing`：`LoadingIndicator` + 固定文案 `CHAT_QUEUE.queuing`，**文案在任意时长后都不变化**；输入区 `disabled`，placeholder 明示「接入人工客服后可继续发送」；
- `?state=connected`：坐席条 + 一条开场语；已接入态发送**只回显用户自己的消息**，不生成坐席回复；
- 两态均不带取消排队按钮 —— 原型未画，且取消后的目标态无依据。
